# Automated control checks (evidence from source systems)

**Built 2026-11-04, Jasmine Alexander (ISSO).** Eleven checks read Counterpart's own AWS account directly through the AWS APIs and answer the questions an auditor would otherwise answer with screenshots. Each result is saved as dated evidence and mapped to SOC 2, ISO/IEC 27001:2022 Annex A and NIST SP 800-53 Rev. 5.

The point is continuous assurance: the evidence is generated by code, it can be rerun at any time, and a control that drifts shows up as a failure instead of waiting for the next audit.

## How results are reported

| Status | Meaning |
|---|---|
| **PASS** | The control is in place, from the account's own settings |
| **FAIL** | A gap. The detail line names what and where (for example, which bucket lacks versioning) |
| **ACCEPTED** | A known gap covered by a risk-register entry in [`compliance/exceptions.json`](../../compliance/exceptions.json), shown with its risk ID and review date. **When the review date passes, it counts as a failure again**, so exceptions can't quietly become permanent |
| **ERROR** | The check couldn't run (for example, a missing permission). Treated like a failure: an unchecked control is not a passing control |

Two exceptions are expected today: **C-03** (GuardDuty off, risk R-12, decision D-09) and **C-06** (the sign-in role has AdministratorAccess, risk R-02, POA&M P-02, review by 2026-11-30).

## Safeguards

- **Read-only.** Only Get, List and Describe calls, plus generating the IAM credential report. A test fails if any other call appears.
- **No secrets in evidence.** Results contain settings and names only; the AWS account number is masked to its last four digits everywhere.
- **Tested without AWS.** `tests/test_compliance_checks.py` runs every check against fake AWS responses: a compliant account passes, each kind of gap fails, a check that can't run is an error, exceptions expire, and the account number never appears. Making errors count as passes, or letting expired exceptions stand, makes the tests fail.

## Running it

From CloudShell in the Counterpart account (boto3 is already installed):

```bash
cd ~/ai-vendor-risk-isso-lab && git pull
python3 -m compliance.run
```

It prints one line per check and saves `evidence/controls/YYYY-MM-DD_aws_control-checks.json`.

**Why it isn't scheduled yet:** a scheduled run from GitHub would need AWS credentials in GitHub, and this account blocks GitHub's short-lived OIDC credentials (D-14), while stored keys were ruled out. Until the app layer exists, the checks run by hand monthly with the POA&M review. The planned home is a scheduled Lambda function in the account itself, using a read-only role.
